# 大范围任务分批执行

适用于全产品、大模块、多菜单或范围超过一个最小标题的测试设计任务。

## 分批原则

- 正式生成用例前先遍历菜单与标题层级，形成批次队列。
- 每批严格对应一个最深可识别的最小标题路径。
- 禁止把多个最小标题合并为一批，也禁止继续拆分一个最小标题。
- 当前批次只处理当前最小标题路径，不预生成后续批次正文。
- 每批完成质量自检后再进入下一批。

## 每批覆盖

每批都必须独立完成：

- 模块定位粗遍历只确定当前批次位置、入口、依赖和范围；当前最小标题内独立执行基线元素盘点、业务流程动态深探、新增元素补充、收口复查和深探准出。
- 初步风险分流、页面可验证项定向补探、剩余事项用户确认，以及用户补充后的必要补探回环。
- 功能、异常、边界、权限、状态和数据一致性用例。
- DFX 适用性评估与性能测试设计。
- 以功能点为父分组，将当前最小标题内的业务流程、步骤、元素、接口和数据对象展开为单主 DFX 原子场景，并在生成用例前完成精确去重。
- 风险与待确认问题。
- 自动化建议与页面元素覆盖清单。
- 正式测试设计 Excel 和独立测试系统导入文件，两者必须同时生成。

## 中间文件控制

- 禁止使用单个 Python、JSON、CSV、Markdown 或文本文件承载多个批次或全产品的完整用例正文。
- Python 中间脚本建议小于 200KB，JSON、CSV、Markdown、TXT 建议小于 256KB。
- 中间文件应按当前最小标题路径、页面域或功能块拆分，用完即清理。
- 正式交付成功后清理本批 `debug_*`、`fix_*`、`regen_*`、分片脚本、`__pycache__`、临时结构化数据、中间 Excel 和非交付截图；不新增清理器或常驻中间目录。
- Python 只承载模板填充或格式转换逻辑；中文数据优先从 UTF-8 结构化文件读取，并通过 `repr()` 或 `json.dumps(..., ensure_ascii=False)` 安全写入。禁止全局替换 Python 源码引号；复杂、多行或包含嵌套引号的逻辑不得放入 `python -c`，应写入当前批次小型脚本并预检后执行。

## 汇总原则

全部批次完成后，只生成跨模块汇总、回归范围、风险清单和客户总览，不重新生成各批完整用例。
