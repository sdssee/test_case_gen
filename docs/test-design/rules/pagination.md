# 分页控件深探与用例设计

本规则只在页面、DOM、截图、原型或可访问性信息中出现分页证据时追加读取。目标是完整覆盖当前产品实际具备的分页能力，不按常见组件外观虚构首页、末页、省略号或其他控件。

## 触发与能力盘点

- 出现总条数、当前页、页码、每页条数、首页、末页、上一页、下一页、跳至某页、页码输入、省略号或其他明确分页语义时，立即按本规则处理；不得依赖 Element UI、Ant Design 等特定框架类名。
- 分页区域不能只登记为一个笼统的“分页组件”。必须按页面实际存在的能力分别盘点总条数、首页、上一页、页码按钮/当前页、下一页、末页、前后省略号、每页条数和跳页输入；非交互展示项可作为观察点，交互项必须分别进入页面元素覆盖清单。
- 单页状态未出现的控件不得直接判定不存在。切换到首页、中间页、末页或更多页数后必须重新扫描分页区域，动态出现的新控件继续补入现有覆盖清单。
- 只有实际观察到的控件才能标记为页面实探；尚未出现但测试设计需要考虑的能力只能写为设计预期，待执行验证，不得伪造控件文案、禁用态或跳转规则。

## 状态与测试数据

- 以页面实际默认页容量 `P` 为基准，按当前任务可安全获得的数据处理空数据、少于一页、刚好一页、`P+1` 首次产生第二页，以及首页、中间页、末页和足够触发动态页码/省略号的状态。
- 能使用本次创建且带测试标识的数据时，优先构造多页状态并完成定向深探；不得询问用户是否需要继续深探。
- 无法安全造数或受环境、权限、接口、关联数据限制时，记录客观原因和所需数据条件。数据不足只影响实探证据等级，不减少分页场景和用例；未执行结果统一标记为设计预期，待执行验证。
- 分页操作后核对当前页、页容量、总条数、目标页数据切片及按钮状态；能够获得多页数据时，同时检查跨页数据无重复、无遗漏。

## 原子场景与 DFX

- 首页、上一页、页码选择、下一页、末页、前后省略号和有效跳页的动作或目标状态不同，页面实际存在时分别形成原子场景；第一页/最后一页禁用态、非法页码和空输入按控件实际能力补充边界或异常场景。
- 每页条数是分页专项例外：每个实际可选页容量都会改变容量边界、总页数或数据切片，必须分别形成场景和功能用例，不使用普通选择类控件的代表性选项抽样。
- 动态深探队列中的页容量父目标必须记录 `branch_policy=逐项验证` 和全部实际 `discovered_values`，每个容量值建立带 `parent_id`、`branch_value` 及独立状态证据的子目标；缺少任一分支时通用深探门禁不得准出。
- 原子场景只在动作、前置状态、测试数据和观察点均相同时合并；不得用一条“分页功能正常”或一条代表性容量用例代替不同状态转换。
- DFT功能覆盖翻页、跳页、正常和边界操作；DFB业务覆盖总数与数据切片准确；DFR可靠覆盖筛选、刷新、删除或数据变化后的页码一致；DFU可用覆盖当前页反馈和禁用态；存在大数据或响应要求时追加 DFP性能，存在适配要求时追加 DFC兼容。不得机械展开能力 × 全部 DFX。

## 用例与专项准出

- 每条分页用例从系统入口开始，写明造数或数据前置、目标页操作、页面/数据结果和必要恢复或清理；页面已有数据只执行查看与分页，不改变其状态。
- 页面元素覆盖清单中的实际分页交互项必须关联对应功能用例；同一个每页条数控件可以关联多个容量用例，但不能把多个实际能力合成一个元素后遗漏用例。
- 分页专项准出必须同时满足：实际分页能力均有处理结果；单页、首页、中间页、末页及动态控件状态已实探或写明客观原因；每个实际页容量都有独立场景和用例；数据不足未导致场景删除；页面实探与设计预期已区分；最终收口不再产生新的分页元素。
- 未通过分页专项准出时，不得宣布页面深探完成，不得进入 DFX 汇总或正式用例生成。
