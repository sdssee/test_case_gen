# 页面实探与元素覆盖规则

## 页面材料处理

涉及页面、截图、原型、页面 URL、菜单路径、浏览器或 computer use 时，必须先识别页面元素，再生成或补充用例。

材料优先级：

1. 需求、用户故事、验收标准和业务规则。
2. 用户提供的文档、截图、原型图、操作说明。
3. 可访问页面的实际 DOM、可见文案、菜单、按钮、链接、图标按钮、下拉项、开关、输入框、弹窗和表格行操作。
4. 浏览器或 computer use 观察到的页面行为。
5. 无法确认的信息登记为待确认问题。

页面实探台账的说明性元数据必须直接使用中文：元素类型使用按钮、图标按钮、输入框、下拉框、单选框、链接、表格列头等；交互方式使用点击、输入、选择、展开、关闭、确认、取消等；发现方式使用页面实探、浏览器实探、截图、需求文档、用户说明等。元素名称/文案必须保留页面实际显示内容，即使其为英文；ID、URL、代码和必要技术术语也保留原文。

## 粗遍历边界

- 粗遍历只用于确认当前模块在整体产品中的位置、入口与导航路径、上下游模块或主要依赖，以及本次需要深探的页面、最小标题或功能范围。
- 粗遍历只输出简短的模块定位摘要和深探批次队列，不枚举全部页面元素，不展开控件，不验证交互，不输出详细字段规则或精确页面风险。
- 粗遍历不得认定元素已经覆盖，不得推断按钮、字段、图标、排序、分页、提示或状态变化的具体行为，不得替代深探、DFX 评估或测试用例设计。
- 粗遍历的唯一作用是为深探确定产品上下文和执行范围；页面事实必须来自后续深探、文档或用户明确说明。

## 深探执行策略

深探采用“初始全区域元素盘点 → 业务流程动态深探 → 新增内容持续补充 → 最终收口复查”的循环。页面元素覆盖清单是贯穿深探过程的动态台账，不是结束时一次性补写的静态结果。

### 初始全区域元素盘点

- 当前批次存在可访问页面、原型或桌面窗口时，先等待页面进入稳定可观察状态，再按标题与工具区、导航与页签、查询筛选区、主操作区、内容与表格区、表头与行内操作区、分页与底部、弹窗/抽屉/浮层以及滚动后区域进行一次基线扫描。
- 基线扫描必须同时关注按钮、链接、菜单、Tab、输入、选择、开关、上传下载、导入导出、预览、排序、分页、批量操作、更多操作、禁用态、空状态、错误态，以及无文字、弱化显示、仅悬停或聚焦后显示信息的图标和控件。
- 无法立即判断功能的可交互元素也必须先进入覆盖清单并标记 `功能不明：`，不得因缺少文字、位置边缘或不属于主流程而忽略。
- 在可用时用 DOM、可见页面和无障碍信息交叉补充盘点；DOM 中不可见或不可操作的隐藏节点不得伪装为已实探元素。

### 业务流程动态深探

- 基线盘点后按功能点和业务流程组织探索，不随机点击，也不要求先把所有元素验证完成后再处理动态内容。
- 每次操作都要观察页面、数据、状态、提示和可恢复路径；操作产生的新字段、按钮、图标、下拉项、弹窗、抽屉、页签、状态或业务分支必须立即补入覆盖清单，并沿当前流程继续深探。
- 对会打开弹窗、抽屉、下拉浮层、编辑态或删除确认框的元素，深探记录必须形成 `触发元素 → 状态出现 → 状态内操作 → 终态动作 → 页面/数据结果` 的完整链路；终态动作必须在页面上实际执行，不能只根据预期结果推断已经关闭、取消或保持不变。
- 当前分支必须走到成功、失败、取消、关闭、返回、数据不变或保存前校验等安全闭环，再返回处理同级其他元素。
- 页面所有已识别元素必须关联功能用例 ID、标记不适用、标记不测范围，或登记带客观原因的未解决事项；相同区域、相同元素和相同状态只记录一次，已有充分证据的流程不重复执行。
- 页面元素是 DFX 分析对象，不是固定的用例拆分单位。同一业务闭环中的多个元素可以关联同一组场景和用例；只有角色、状态、数据、动作、环境、观察点或恢复路径发生实际变化时才展开新场景，禁止机械展开元素 × 12 × 4。

### 风险分流与定向补探

- 完成主要业务流程后，将已发现风险按可验证性分流：页面或 DOM 可验证、可用本次测试数据验证、需接口/日志/环境/权限/联调支持、需用户做业务范围或规则决策。
- 页面或 DOM 可验证的内容必须先定向补探，不得直接询问用户；可用测试数据验证的内容应在数据安全规则允许范围内完成验证。
- 只有穷尽当前页面、DOM、现有文档和安全测试数据后仍无法确认，或确实需要业务取舍的内容，才进入风险与待确认问题并提交用户确认。
- 用户补充中出现“需要验证”“需要覆盖”“需测试”“测试时确认”“进一步检查”等要求时，必须重新判断是否可实探；可实探时先形成定向补探任务，完成后再次收口和判断深探准出，再进入 DFX 和用例设计。
- 用户提供业务规则不能替代页面行为验证；规则已明确但真实提示、校验位置、状态变化或恢复路径未知时，仍需继续实探。

风险分流和补探过程使用现有字段记录，不新增 Sheet 或列：`发现方式` 区分需求文档、页面/DOM、浏览器实探、computer use、用户说明；`业务依据/规则来源` 记录实际依据；未解决事项在 `待确认问题/备注` 使用 `待实探：`、`待确认：`、`未验证：`、`需验证：` 或 `功能不明：` 前缀。

### 最终收口复查

- 完成业务流程和定向补探后，按初始区域顺序再检查一次，核对基线元素是否全部有处理结果，以及状态变化、滚动、悬停、聚焦、弹窗、抽屉和下拉内部是否产生新元素。
- 收口复查发现新元素时，将其补入覆盖清单并返回动态深探；处理完成后再次判断准出条件，不重复执行已经有充分证据的完整流程。
- 最后一次收口复查没有产生新的待处理元素，才允许进行深探准出判断。

## 深探完成门禁

- 深探准出必须同时满足：当前范围内页面和子区域均已处理、基线元素都有处理结果、动态新增元素已继续深探、主要业务流程已形成安全闭环、页面可验证风险已完成定向补探、未执行项均有客观原因、证据来源已区分，且最后一次收口复查没有产生新元素。
- 真实状态变化元素只有在上述五段链路已经执行并关联用例后才可标记 `已覆盖`；安全边界内可操作却未执行终态动作的元素仍属于待实探，无法操作时写明客观原因。未实际观察的终态只能写成 `设计预期，待执行验证`。
- 无法证明满足任一准出条件时，按未完成处理；不得以“信息已经足够”主观宣布深探完成。
- 仍存在“功能不明、待实探、需点击验证、需输入验证”的可操作元素时，不得结束深探、不得提交用户做业务确认、不得进入 DFX 或用例生成。
- 允许的未执行原因仅包括无权限、页面不可访问、测试环境不支持、缺少关联数据、需要接口/日志/联调、需要用户做业务规则或范围取舍、操作存在不可接受的外部影响，或有限重试后仍无法获得证据。
- 单个操作失败时最多正常重试一次，再改用 DOM、页面快照、可见文案或无障碍信息补充观察；仍失败则记录原因，不得无限重试、循环刷新或反复登录。
- `发现方式=浏览器实探/computer use/页面或DOM` 只能用于实际观察到的结果；用户说明必须标记为 `用户说明`，不得伪装为页面实探。
- `覆盖状态=已覆盖` 时不得保留以 `待实探：`、`待确认：`、`未验证：`、`需验证：` 或 `功能不明：` 开头的未解决备注。

## 深探准出后的 DFX 与场景映射

- 只有深探通过准出门禁后，才允许开始 DFX 与测试场景映射；DFX 不得用于补偿尚未完成的页面实探。
- 页面元素覆盖清单中的每个可交互元素必须填写适用 `DFX维度` 与 `DFX场景`；已生成用例的元素不得缺失 DFX 映射。
- 将元素、接口或数据对象写入 `测试场景矩阵` 的 `测试对象/页面元素`，每个场景行只保留一个主 DFX 维度与场景。

## 选择类控件

- 下拉框、级联选择、单选框、复选框、树选择、枚举筛选等选择类控件不得只展开查看选项。
- 必须选择代表性选项，观察后续字段、二级/三级下拉、列表数据、按钮禁用态、校验提示、默认值、清空重置、搜索结果和提交前提示变化。
- 对存在前后依赖的控件，必须记录每个关键选项触发的联动/依赖变化；无联动也要明确记录为无联动变化。
- 结果写入页面元素覆盖清单，并反映到功能测试用例的操作步骤和预期结果。

## 输入类控件

- 输入框、搜索框、文本域、数字框、日期框、URL/地址、端口、邮箱、手机号、名称、编码等输入类控件不得只观察字段存在。
- 必须实际输入正常、异常、边界或用户提供的测试数据，触发查询、下一步、测试连接、预览、保存前校验等后续动作。
- 必须记录真实提示、字段校验位置、后续页面、结果分支/后续状态、禁用态和可恢复路径。
- 结果写入页面元素覆盖清单，明确输入值、观察行为和结果分支。

## 新增类流程

- 新增、创建、添加、新建、保存、提交、下一步、完成、测试连接等新增类流程必须实填实走。
- 在安全边界内实际填写测试数据并触发后续动作。
- 成功时必须进入详情页、下一级页面或后续配置页继续观察可点击/可输入/可测试功能。
- 失败时必须记录真实失败提示、停留页面、字段校验位置、可恢复路径和是否允许重新提交。

## 既有数据只读深探

- 对既有数据必须主动做只读深探：打开详情、进入编辑页观察字段和联动、尝试点击删除/停用/提交等危险按钮以打开确认弹窗或保存前校验。
- 不得点击最终确认、保存、提交或改变既有数据状态。
- 必须记录确认弹窗、二次确认、权限提示、取消路径、返回路径。
- 可以复制既有数据的字段，改名或改编码为带 `AI_TEST`、`CODEX_TEST`、当前日期或任务编号的新数据后新增，再用新数据探索后续页面。
